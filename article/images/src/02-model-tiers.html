The sub-agent model tiering rule

Every sub-agent gets a model assigned explicitly, chosen by task complexity — never inherited by default
TierUse it forExamples
Small model Mechanical work that executes ready instructions Renames, fully specified edits, transcription
Mid-tier model Normal work — the floor for anything that reasons from prose Multi-file changes, debugging, standard reviews
Top model Hard judgment only Architecture, design trade-offs, the final whole-branch review
Learned the hard way: turn count beats token price. A cheap model that needs three times more turns costs more than a mid-tier model that finishes in one.
